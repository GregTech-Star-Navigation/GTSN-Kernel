# 接口

> 状态：一期。最后更新 2026-11-14。

## 游戏内命令

### `/gtsnperf`

权限等级 ≥ 2。

| 用法 | 作用 |
| --- | --- |
| `/gtsnperf` | 输出各阶段 avg / p50 / p99 / max，以及线程越界计数 |
| `/gtsnperf reset` | 清空样本 |
| `/gtsnperf on` | 开启采集 |
| `/gtsnperf off` | 关闭采集（`begin/end` 立即返回，开销为零） |
| `/gtsnperf hash [blocks]` | 世界状态哈希（一致性测试用） |
| `/gtsnperf csv` | 开始/停止录制明细 CSV |

## CSV 格式

路径：`<gameDir>/gtsnperf/gtsnperf-<yyyyMMdd-HHmmss>.csv`

每 tick 一行，单位毫秒，保留三位小数。空值表示该阶段本 tick 未采样。

```csv
tick,server_tick,server_children,functions,level_tick,chunk_cache,chunk_map,level_ticks,raids,entities,block_entities,entity_sections,connections,players,save
1198,0.711,0.699,0.007,0.007,0.003,0.001,0.001,0.000,0.000,0.000,,0.001,0.001,
```

列名与 `TickStage.key()` 一一对应，**稳定**（不随显示文案变化）。新增阶段只会在末尾追加列。

每 200 行 flush 一次；进程被强杀最多丢 200 tick。

## JVM 参数

| 参数 | 作用 | 默认 |
| --- | --- | --- |
| `-Dgtsnkernel.perf.logEvery=<tick>` | 每 N tick 把摘要写日志 | `0`（关闭） |
| `-Dgtsnkernel.perf.csv=true` | 服务端启动即开始录 CSV | `false` |

`build.gradle` 的 `runServer` 已默认开启这两个（`logEvery=200`、`csv=true`），方便开发时直接看。

## 内部 API

一期只实现了 `perf` 包；其余是二/四/五期的骨架，**接口已定但无实现**。

### `com.gtsn.kernel.perf`（已实现）

```java
// 打点：在任意位置 begin/end，嵌套安全（不同阶段各占一个时间槽位）
StageProfiler.begin(TickStage.ENTITIES);
// ... 原版逻辑 ...
StageProfiler.end(TickStage.ENTITIES);

// 统计（会分配数组排序，只应在命令触发时调用）
StageProfiler.Stats stats = StageProfiler.stats(TickStage.ENTITIES);
// stats.count() / avgMs() / p50Ms() / p99Ms() / maxMs()

// 只采集绑定线程的数据
StageProfiler.bindOwner(serverThread);
```

采集器**无锁、无每 tick 分配**：环形缓冲预分配 1200 槽位（60 秒 @ 20 TPS），`begin/end` 只做一次 `System.nanoTime()` 与数组写入。

### `com.gtsn.kernel.core`（二期 2a 已实现）

```java
// 区块 → region（固定网格，每边 16 区块）
RegionMap map = RegionMap.grid(16);
RegionId id = map.regionOf(chunkX, chunkZ);   // 负坐标用 floorDiv，不会和正坐标混

// 串行调度
SerialRegionScheduler scheduler = new SerialRegionScheduler(map);
scheduler.activate(new RegionId(0, 0), "chunk-load");
scheduler.activate(new RegionId(1, 0), "chunk-load");

// 跨 region 同步访问：检测到环（含间接环）会自动合并
scheduler.recordSyncAccess(new RegionId(0, 0), new RegionId(1, 0), "hopper-pull");  // false
scheduler.recordSyncAccess(new RegionId(1, 0), new RegionId(0, 0), "hopper-pull");  // true，已合并

// 串行 tick（按 RegionId 排序，顺序确定）
scheduler.tickAll(region -> {
    // 对该 region 执行一次 tick
});

scheduler.mergeCount();   // 已发生的合并次数
scheduler.regions();      // 只含代表，已排序
scheduler.parallelism();  // 二期恒为 1
```

**合并语义**：`merge` 保留 `compareTo` 较小的作为代表（可复现）；合并单向不可逆；重复合并不计数。

**环检测**：加边前先 DFS 判断 `target` 能否到达 `source`，能到达说明闭合环 → 合并。只查直接
反向边不够 —— `A→B→C→A` 的三角环同样会死锁。

### `com.gtsn.kernel.core`（二期 2b 待实现）

```java
public interface AccessProxy {

    boolean write(RegionId regionId, String what, Runnable mutation);
    <T> Optional<T> sync(RegionId regionId, String what, Reader<T> action, long timeoutMs);
}
```

`AccessProxy.sync` 的契约：**实现必须做依赖环检测**。检测到成环时调用 `TickScheduler.merge`，
而不是等待 —— 等待就是死锁。

### `com.gtsn.kernel.compat`（骨架）

```java
public record CompatRule(
        String modId,
        int affinityRadius,      // 区块亲和半径
        boolean exclusiveThread, // 独占线程（最保守）
        List<String> staticUnsafe,
        String reason) {}

CompatRules.of("create");                    // 未声明返回 DEFAULT
CompatRules.put(CompatRule.exclusive("mekanism", "静态网络缓存无锁"));
CompatRules.affinityRadiusFor(List.of("create"));  // 取最大值
```

### `com.gtsn.kernel.gen`（骨架）

```java
public interface GenerationScheduler {
    <T> CompletableFuture<T> request(int chunkX, int chunkZ, String target, Generator<T> generator);
    <T> void inject(int chunkX, int chunkZ, T data, Runnable onInjected);
}
```

三条约束（地形 mod 必须遵守）：
1. 生成阶段完全不碰 `Level`
2. `inject` 在目标 region 线程执行
3. 同一 `ChunkPos` 同时只有一个生成任务（内核保证）
